# Security

## Supported versions

The latest release only. Fixes ship as a new SemVer tag; there are no backports.

## Reporting

Use GitHub's private vulnerability reporting on this repository (Security → Report a vulnerability). Don't open a public issue for anything that could expose the Web UI password or put torrent traffic outside the VPN.

Include `port-sync.ps1 -Version`, your Windows, Proton VPN and qBittorrent versions, and the relevant `sync.log` lines. `sync.log` never contains the password.

I read reports within a week. If it's real, the fix and the changelog entry name the problem plainly.

## What this tool handles

- Network: HTTP to the qBittorrent Web UI at `-QbitUrl` (default `127.0.0.1:8080`), nothing else. The installer also downloads `port-sync.ps1` from `raw.githubusercontent.com` over HTTPS and checks it is that script before replacing anything.
- Password: generated by the installer (96 random bits), stored in `%LOCALAPPDATA%\port-sync\qbit-pass.txt` with `ConvertFrom-SecureString`, which is DPAPI under the current Windows account. Only that account on that PC can decrypt it.
- Login: one Web UI session per check, logged out straight after. After a rejected login it waits 30 minutes or for the password file to change, so it doesn't walk qBittorrent into its 5-failure ban.
- Privileges: the scheduled task runs as you, not elevated. Admin rights are used once, through UAC, to register the task.
- It reads the Proton VPN app's log and never writes to it. It doesn't touch the VPN, the kill switch or qBittorrent's network binding; those stay as the [setup guide](docs/setup-guide.md) sets them.

## Out of scope

The Proton VPN app and qBittorrent themselves: report to [Proton](https://protonvpn.com/support) and [qBittorrent](https://github.com/qbittorrent/qBittorrent/security).
