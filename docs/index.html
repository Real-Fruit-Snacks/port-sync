port-sync

Keeps qBittorrent's port synced to Proton VPN

Proton VPN hands out a new forwarded port on most reconnects. Until qBittorrent listens on it, peers can't connect in. port-sync reads the port from Proton's log every 15 seconds and sets it in qBittorrent.

irm https://raw.githubusercontent.com/Real-Fruit-Snacks/port-sync/main/install.ps1 | iex
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Real-Fruit-Snacks/port-sync/main/install.ps1))) -Uninstall
Run it in a normal PowerShell window as the account you torrent with. It makes a Web UI password, tells you where to paste it in qBittorrent, does one test sync, then registers a task that runs at sign-in. One UAC prompt, for the task.
sync.log
2026-10-26 08:14:02 [port-sync] port-sync 2.0.0 watching
  C:\Users\you\AppData\Local\Proton\Proton VPN\Logs
2026-10-26 08:14:02 [port-sync] listening port updated:
  49160 -> 48213
2026-10-26 09:02:17 [port-sync] listening port already
  correct: 48213

# Proton log:  Port pair 48213->48213
# qBittorrent: listen_port = 48213

Why

Windows has no port file

On Linux the Proton app writes the forwarded port to a file. On Windows it only writes it to its own log, so every reconnect means opening qBittorrent's settings by hand, or a slow torrent until you notice.

port-sync assumes the VPN and qBittorrent are already set up so torrent traffic can't leave outside the tunnel. The setup guide is that setup, step by step: kill switch, adapter binding, port forwarding, a leak test.

How it works

Every 15 seconds

The password is DPAPI-encrypted to your Windows account and only ever sent to the Web UI on 127.0.0.1.

  1. Checks that the ProtonVPN adapter is up.
  2. Reads the newest Port pair line from Proton VPN's client-logs.txt.
  3. Logs in to qBittorrent's Web UI and reads its listening port, at most once a minute when Proton's port hasn't changed.
  4. If they differ, sets qBittorrent's port and checks that it took, then logs out.
  5. Writes one line to sync.log per change. After a rejected login it waits for the password file to change, or 30 minutes, because qBittorrent bans an address after 5 failures.

Day to day

Watch, test, restart

# watch it
Get-Content "$env:LOCALAPPDATA\port-sync\sync.log" -Wait -Tail 20

# one cycle: exit 0 if qBittorrent has the forwarded port, 1 if not
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\port-sync\port-sync.ps1" -Once

# restart the task
Stop-ScheduledTask port-sync; Start-ScheduledTask port-sync

Coming from proton-qbit-port-sync 1.x: run the same install line. It keeps your password file, replaces the old task, and moves to %LOCALAPPDATA%\port-sync.

Configuration

Parameters

Defaults fit the setup guide. To change one for the task, edit its arguments in an admin PowerShell (Get-ScheduledTask, Set-ScheduledTask); the README has the exact lines. Re-running the installer resets them.

ParameterDefault
-QbitUrlhttp://127.0.0.1:8080
-QbitUseradmin
-ProtonLogs%LOCALAPPDATA%\Proton\Proton VPN\Logs
-AdapterProtonVPN; ProtonVPN TUN for OpenVPN, '' to skip the check
-StateDir%LOCALAPPDATA%\port-sync
-IntervalSec15, how often to read the Proton log
-RecheckSec60, how often to re-read qBittorrent's port

Tested on

  • Ubuntu 24.04 · PowerShell 7.4.6 · qbittorrent-nox 4.6.3: the Pester suite, including the sync against a real Web UI, with simulated Proton log lines
  • Windows Server 2022 (GitHub windows-latest) · Windows PowerShell 5.1 and PowerShell 7: unit tests, and the installer against a real Task Scheduler
  • Not tested: the Proton VPN app's real log on a Windows 10/11 desktop, and qBittorrent 5.x. An issue saying which versions worked is welcome.

Known issues

  • Proton doesn't document the Port pair log line. If an update changes it, sync.log says so and nothing else breaks.
  • A console window can flash at sign-in.
  • The password file is encrypted to the account that created it: install as the account you torrent with.
  • qBittorrent has to be running to receive the port; a change made while it's closed lands within 60 s of opening it.
